# 独立复核请求

请在不读取原建模/调试对话的条件下，核对本包中的官方问题、模型、所选计算后端、正式运行和结果。先验证包内 digest 与 upstream freshness；不要用旧包复核新结果。

重点确认：

1. 模型是否回答了题目真正要求的问题；
2. 目标方向、上下界、单位、约束和物理含义是否一致；
3. 是否存在重复计量、遗漏变量、跨问矛盾或无依据外推；
4. 代码是否实现了文档声明的模型；
5. 结果是否来自保存的正式运行，并满足官方约束；
6. **每条结论声明的 `scope` 是否被真正验证过**——见下；
7. 哪些结论可进入论文，哪些属于 P0、P1 或 P2。

关于第 6 点：逐条对照结论声明的适用范围与实际验证过的范围。若结论只在推导它的那一个点上被检验（单组参数、边界值、样本内），而 `scope` 声称它适用于一个范围，则未验证。对给出决策规则、阈值或所选策略的结论，"验证范围"指报告它在标称点之外的表现，而不只是它在标称点最优。一条在设计点正确、在别处失效的规则是 P0，不是表达问题。

P0 与 P1 的分界不是严重程度，是种类。P0 是一致性失败：声称的多于验证的，或同一件事的两处记录不一致——这类判断靠读就能定，不依赖复核人的品味。P1 是在已验证范围之内做出的判断。一条只要把 `scope` 写窄就能消解的发现，属于 P0 而不是 P1。

P0：真实错误、答非所问、声明范围超出验证范围、代码/结果/论文不一致、假设与题面条件冲突、严重 provenance 问题。
P1（均在已验证范围内）：模型选择、假设强度、baseline 偏弱、验证或敏感性不够充分、拟合有限。
P2：表达、图表或额外实验建议。只有开放 P0 可以给出 `revision_required`。

若本包是 targeted re-review，先读取包根目录的 `TARGETED_FINDINGS.json`。它已包含目标 P0 的 finding ID、category、location、evidence 和 recommendation；无需访问完整旧 review。优先检查这些既有 P0 是否解决。可以报告新 P1/P2，但不要把它们升级成阻断项；只有新发现且有明确证据的 P0 才能新增阻断。
