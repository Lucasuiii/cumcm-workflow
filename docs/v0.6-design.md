# v0.6 设计：有界反馈、自动取证、更少的自述

v0.6 不是在 v0.5 骨架上继续加规则，而是把工程投入从"检查模型有没有声称自己做过"搬到"替模型把事情做掉并自动留证"。判断标准很直接：schema 数量下降，脚本数量上升，需要手写的契约下降。

| | v0.5 | v0.6 |
|---|---|---|
| JSON Schema | 22 | 21 |
| 脚本 | 15 | 19 |
| 需要手写的契约 | 14 | 9 |
| 状态旋钮 | mode × profile × gate-mode（8 组合） | mode × gate-mode（4 组合） |

## 1. 机器事实与语义判断分开

这是 v0.6 的中心线，也应当是读这个仓库时记住的唯一一句话：

> **tooling 记录机器事实，agent 写语义判断。**

argv、时间、exit code、stdout/stderr、SHA-256、`sha256-tree-v1` 源码树、PDF 页数与哈希、locator 取出的数值、编译日志里的 overfull/undefined reference/missing glyph——这些一律由脚本观察。problem facts、模型、claims、论文计划与正文——这些才是 agent 的工作。

新增记录器：

- `record_run.py` 包装执行并写出 `RUN_MANIFEST.json`；
- `index_result.py` 通过 locator 读回数值写入 `RESULTS_INDEX.json`；
- `record_compile.py` 编译论文并写出 `COMPILE_RECEIPT.json`，逐页渲染，从日志派生 layout checks；
- `refresh_evidence.py` 重算已声明文件的 size/hash 元数据。

一个结构性后果：`index_result.py` 从 locator 读值之后，`RESULT-E012`（索引值与执行输出不一致）在结构上不再可能发生。这条检查过去实质上是在检验"agent 有没有把数字抄对"；正确的修法是让它不用抄。

记录器**只观察，不判断**。它不扫描"运行后新出现的文件"来猜 outputs，不自动把运行提升为 official，不替你决定哪个 run 支撑哪个 result。只有 flag，没有配置文件，没有 DSL。

## 2. Deferred Model Selection

真实建模是 `粗模型 → 试算 → 比较 → 回改 → 冻结`，而不是一次性写对合同再执行。

- `working` 模式下 `MODEL_CONTRACT` 的每个 component 只需要 `model_id`、`capability_ids`、`method`、`scope`。
- `variables` / `inputs` / `outputs` / `verification_plan` 在进入 `finalizing` 时才强制（由 `check_model` 按 mode 判断，不再写死在 JSON Schema 的 `required` 里）。
- `CROSS_QUESTION_LEDGER.json` 从必需降为"存在即检查"。
- `MODEL_CANDIDATES.md` / `OPTIMALITY_SCOPE.md` / `VALIDATION_PLAN.md` / `ASSUMPTIONS.md` / `SYMBOLS.md` 明确是笔记而非契约。v0.5 里 `VALIDATION_PLAN.md` 是复核打包器的隐藏硬依赖而检查器从不提它，这个洞已经补上。

**不延后的是能力归属。** `CAP-E008`（每个 capability 有可失败的验收检查）和 `CAP-E009`（每个小问有 capability 负责）在两种模式下都是 error。"答非所问"是这套工作流存在的首要理由，而它不随模型换代而失效——所以这个不变量挂在 churn 率最低的契约（`TASK_CAPABILITIES.json`）上，而不是挂在最不稳定的模型合同上。

冻结时新增一条实质检查：`verification_plan` 的条目要能对应到 official run 真实记录的 assertion 名。没有任何已执行断言的冻结模型报 `MODEL-E009`；有断言但计划条目对不上的报 `MODEL-W010`。这把验证计划从散文变成了"运行必须满足的东西"。

延后冻结有一个真实风险：冻结后的合同可能退化成对已写好代码的事后描述。机器只能查到上面那一条；剩下的写进了 `REVIEW_REQUEST.md` 的失败类清单，交给 fresh-context reviewer 判断。

### 候选比较是结构化的

v0.5 的 `alternatives_considered` 是一个自由字符串数组，检查器只验证"非空"，也就是说"我比较过其它方案"是一句无法证伪的话。v0.6 把它换成结构化的 `candidates`：

| 字段 | 作用 |
|---|---|
| `candidate_id` | 让运行可以指向它 |
| `why_considered` | 为什么值得考虑 |
| `discriminating_evidence` | **用什么观测把它和别的候选分开** |
| `status` | `under_evaluation` / `selected` / `rejected` |
| `evaluation_run_ids` | 真正评估过它的运行 |
| `decision_rationale` | 凭什么选中或淘汰 |

`record_run.py --candidate <id>` 把探索运行绑到候选上。于是"选择 A"不再是一句声明，而是一条可以核对的链：候选声明了区分证据 → 探索运行评估了它 → 选择引用了那些运行 → 理由说明了运行显示了什么。

检查项：`MODEL-E013`（必须恰好一个 selected）、`MODEL-W014`（选中但没有任何评估运行）、`MODEL-E014`（选中/淘汰没有理由）、`MODEL-W012`（候选说不出区分证据）、`MODEL-E015`/`MODEL-W016`（引用了不存在或没声明评估该候选的运行）。working 期是 warning，冻结时变 error。

`discriminating_evidence` 是这套设计的关键字段。"A 更准确"不是区分证据；"留出窗口上的残差是否超过 5%"是，因为一次运行能回答它。

## 3. 探索运行是一等公民

Deferred Model Selection 的全部收益来自"探索性计算变便宜"，所以 v0.6 让探索运行几乎零成本：

```bash
python3 scripts/record_run.py --project <p> -- python3 code/try.py
```

零 flag，产出一份合法的 `official_run: false` 记录。相应地，检查器对非 official run 全面降级：缺日志、缺 capability、hash 不符、断言失败，都是 warning。v0.5 里 `RUN-E008`（断言失败）不区分 official，一个保留下来的失败实验会直接阻断整条链——这与文档自己的说法矛盾，现在修好了。

同时 `stage_scope_paths("computation")` 只把 official run 纳入 decision scope。v0.5 里新增任何一个探索 run 都会让 computation 的 accepted decision 变 stale，等于让探索行为污染正式批准。

### 运行是追加的，证据是冻结的

最初的 `--rerun` 是就地覆盖：同 ID、同目录，源码快照、输出哈希和 stdout 全被顶掉，`parent_run_id` 还指向自己。这和仓库自己的立场自相矛盾——decisions 是追加的、旧复核会归档，唯独正式运行被就地摧毁。更糟的是它保住了"抄写的副本"（RESULTS_INDEX 里那个数）而销毁了证据本身。

现在 `--rerun` 追加 `RUN-Q1-002` 并把 `parent_run_id` 指向 `RUN-Q1-001`。但只做这一步会引入新问题：被保留的旧运行记录的是**活路径**的哈希，而下一次运行会覆盖那些文件，于是旧运行永远报 `RUN-E020`/`RUN-E007` 误红。所以第二步是把声明的源码和输出冻结进 `runs/<id>/{source,outputs}/`，对副本取哈希。

第三步是别把漂移检测弄丢。冻结副本不可变意味着旧的"快照 stale"判据永远不会触发——而那是全系统最有价值的一条检查。于是 `RUN-E020` 改为比对冻结副本与活文件，语义也更准确了："工作区已经走远了"，而不是"快照坏了"，并且两个版本都还在。

supersession 由 parent 链推导，不回写旧 manifest：回写会改变它的哈希，把所有绑定它的 accepted decision 打成 stale——等于用一个小号的覆盖去修覆盖。

## 4. 真正的 scoped redo

v0.5 的 `--changed/--impact` 和 `trusted_snapshots` 只写进报告，不改变任何检查行为。文档却描述成"局部重验"。v0.6 删掉这套空转的形式，换成 `plan_redo.py`。

确定性检查本身很便宜，所以它继续无条件全查。贵的是**重跑、重复核、重写**，被 scope 的是这三件：

```
code/solve_q2.py 变更
  computation  必须重跑：RUN-Q2-003（source snapshot 失配）
  computation  受影响结果：RES-Q2-001
  validation   targeted re-review 覆盖：F-003；重建复核包
  paper        需重写/复核：paper/sections/40_q2.tex
  delivery     PDF/源码绑定失效，需重新编译
  not affected: RUN-Q1-001, sections/20_q1.tex
```

它反向遍历仓库里已经存在但从未被反向使用过的 ID 图：`official source → fact → capability` 与 `source file → official run → result → claim → section → PDF`。报告里的 `trusted_snapshots` 改名为 `stages_with_current_decision`——它陈述的是"这个阶段的 accepted decision 是否仍然对应当前文件"，这是事实；而不是"我因此跳过了检查"，那是承诺。

## 5. 删掉的自述式治理

- **`PAPER_TRACEABILITY.json` 整个删除。** 它的实质检查只有两个常量加 ID 存在性，而它承诺的性质（内部 ID 不进正文）已经由 `paper_visible_text_check.py` 在渲染后的 PDF 上直接测量。用承诺书去保证一个已被直接测量的性质是纯冗余。
- **envelope 里的 `review` 字段删除。** 正式批准早就只在 `decisions.jsonl` 里。保留 `review` 结构的只剩真正消费它的四处。这一刀省掉 14 个手写契约各 5 个字段的样板。
- **`PAPER_QUALITY_REPORT` 的 8 维 × N 小问矩阵删除**，每小问保留 `status` + `notes`。八个维度检查器只验证"不是 fail"，想过的 agent 全填 `pass` 即可。
- **`paper-plan.schema.json` 的 v0.4 遗留块删除**：`question_argument_chains`、`figure_plan`、`page_budget`、`claims_evidence_matrix`、`reader_narrative`、`reference_reviews`。schema 是给模型看的提示词，留着就会被填。
- **`figure.visual_review` 降为可选**，`axes`/`transformations` 删除（从不被语义检查）。
- **`PTEXT-E007` 删除**：要求对一份机器生成的报告再签一次字，只是多一层自述。
- **`profile`（strict/sprint）整体删除**：它唯一的实际差别是几条规则的严重级，与真实比赛节奏无关。v0.6 只有一套规则。
- 阶段状态从 6 个收缩到 4 个：`not_started` / `in_progress` / `passed` / `needs_revision`。`awaiting_review` 和 `blocked` 从没有被任何脚本写入过。

## 6. 迭代是一条命令

v0.5 里从 computation 退回 model-design 要手改 `state.json`，否则 `STATE-E008` 报错。v0.6 把 reopen 做成 `record_decision.py` 的既有语义：

```bash
python3 scripts/record_decision.py --project <p> --stage model-design \
  --decision revision_requested --decision-id DEC-007 ...
```

它把该阶段及全部下游置为 `needs_revision`，删除对应 snapshot，并把 `current_stage` 移回去。`STATE-E008` 相应放宽——下游处于 `needs_revision` 是重开之后的正常状态，只有下游仍标 `passed` 才是矛盾。`STATE-E007`（前置阶段必须 passed）在 working 模式降为 warning：working 里的阶段状态本来就是自述的，强制排序只增加摩擦、不增加保证。

## 7. 独立复核：保留机制，删掉伪证据

fresh-context review 机制原样保留，包括 targeted re-review 和自包含的 `TARGETED_FINDINGS.json`。改的是那几个把"独立性"编码成 JSON 的字段：

- `conclusions_withheld: true`（恒真，且包里本来就有 `RESULTS_INDEX.json` 和 `MODEL_CONTRACT.json`）替换为 `context_excluded`——打包器**实际排除**了哪些东西：originating task transcript、debug history、failed runs、prior review prose。打包器控制复制过程，所以这句话是真的。
- 结果模板不再预填"独立性成立"。v0.5 的模板把 `different_conversation: true`、`selected_by_user: true`、`independence_grade: context_separated_model_correlated` 都写好了，reviewer 只要填名字就能过——默认值的方向是反的。现在这四个字段是 `null`，留 null 直接失败（`IREVIEW-E027`）。
- `IREVIEW-E026`（两个 task ref 必须不同）保留，但文档不再把它算作独立性证据；它就是一个防复制粘贴的护栏。

## 8. 其他修复

- `paper_visible_text_check.py` 删掉硬编码的 `Documents/Codex`（那是作者本机目录名），ID 正则从 `PREFIX-[A-Z0-9-]+` 收紧为 `PREFIX-[Qn-]NNN`，正文里的 `Model-A`、`RUN-1` 不再被误杀为阻断项。
- `record_compile.py` 让 `layout_report.rendered_pages` 来自真实的逐页渲染，而不是"模型写下 [1..38]"。
- `COMPILE-E006`（字体/缺字检查）不再依赖 profile，且来源是编译日志而非声明。

## 不向下兼容

v0.6 拒绝任何 `schema_version` 不是 `0.6.0` 的契约，且不保留迁移脚本或历史设计文档。维护两条时间线的成本高于它的价值：迁移逻辑要跟着每一次 schema 变化走，而旧工作区的正确升级路径本来就是用官方文件重新初始化——官方输入没变，重新拆题和重跑计算才是诚实的做法。

## 不做的事

- 不再新增 schema、阶段、severity 等级或 digest 种类。
- 不做跨语言 parity 验证。
- 不在独立复核上加密码学/证书机制：同机同模型的独立性本质上无法证明，加机制只增加形式。
- 不做 skip-trusted 式的增量检查：确定性检查不是瓶颈，跳过它省不下真实成本，却会让"检查过了"的含义变模糊。
